## Список требований к внешним интеграциям

### Ролевая модель «Умный дом» и допустимые действия:
- Собственник (homeowner)
  - Допустимые действия: открытие домофона, управление шлагбаумом, управление доступами гостей, просмотр событий своего объекта
  - Внешние API: Домофон, Шлагбаум (через интеграционный сервис)
- Проживающий (resident)
  - Допустимые действия: открытие домофона, управление шлагбаумом, просмотр собственных событий
  - Внешние API: Домофон, Шлагбаум (через интеграционный сервис)
- Гость (guest)
  - Допустимые действия: разовый/временной доступ к домофону/шлагбауму согласно политике, без управления настройками
  - Внешние API: Домофон, Шлагбаум (через интеграционный сервис)

Каждая роль должна быть явно сопоставлена с правами на операции и ресурсами интеграций (RBAC/ABAC), а также с контекстом (объект недвижимости, временные окна).

### Требования к безопасности:
* Изоляция — все вызовы внешних партнёрских API выполняются ТОЛЬКО из выделенного интеграционного сервиса PropDevelopment (единственная точка входа)
* Минимальные привилегии — интеграционный сервис и партнёрские ключи имеют доступ только к необходимым операциям и данным
* Сквозное шифрование — все API общаются по TLS; для партнёров предпочтительно mTLS
* Все ключи интеграций с API партнёров хранятся в защищённом хранилище (HashiCorp Vault), ведётся регулярный аудит доступа
* Все данные от API партнёров валидируются и очищаются от лишних полей на уровне DTO
* Должен быть разработан протокол уведомления об инцидентах безопасности
* Получить от партнёров гарантии о соответствии 152‑ФЗ, если интеграции пересылают персональные данные
* Хранение персональных данных в отдельных зашифрованных хранилищах; сырые данные в DWH — деперсонализованы
* Файлы (номера, биометрия, фото для facial-recognition) хранятся во внутреннем S3-контуре без прямой привязки к клиенту (хеширование)

### Протоколы аутентификации и авторизации:
* Пользовательская аутентификация выполняется ТОЛЬКО в системах PropDevelopment (IdP/Keycloak); партнёрские системы не аутентифицируют пользователей напрямую
* Партнёры доверяют только запросам от интеграционного сервиса компании (сервисные ключи/токены, mTLS)
* Использование JWT/OIDC для клиентских приложений; короткоживущие токены и обновление
* Внедрение MFA для доступа к приложению tenant-app и использования интеграций
* Проверка подлинности запросов между внутренними системами PropDevelopment, подпись/взаимная аутентификация сервисов

### Управление жизненным циклом ключей интеграций:
* Регулярная ротация ключей/токенов партнёрских интеграций (политика ротации и напоминания)
* Процедура немедленного отзыва при компрометации (revoke), блокировка на уровне интеграционного шлюза
* Разделение ключей по средам (dev/test/stage/prod); запрет межсредового использования
* Централизованное хранение секретов в Vault, контроль доступа по ролям, аудит и оповещения

### Организация взаимодействия между системами:
* REST API для общения между мобильным приложением PropDevelopment и внутренними сервисами «Умного дома»
* Выделенный интеграционный сервис — единственная точка входа для партнёрских интеграций (SPI/WS/REST), реализация адаптеров к домофону/шлагбауму
* Фиксированные DTO для взаимодействия с партнёрскими системами
* Централизованное логирование интеграций и ошибок в единой системе (ELK) — интеграционный сервис является центральной точкой логирования; обфускация ПД при логировании
* Версионность API и политика вывода из эксплуатации (deprecation) для устойчивости интеграций
